# 极端作业健康预警

在山火、高原与高温演训等弱网任务中，边缘设备**离线**汇集血氧、核心温度与脑电
生命体征片段，输出带模型版本、输入窗口、规则与校准依据的风险预警，并保留完整的
处置与军医裁决记录。恢复连接后按设备序列安全汇入。

## 设计原则

1. **任务前冻结**：阈值、设备校准、风险方案、任务剖面（高温/高原）在任务开始前
   审定冻结（`fixtures/protocol.json`），生成内容哈希 `protocol_hash`。边缘端只
   持有冻结副本；任务结束后的阈值更新只能用于新任务，旧评估永久钉在旧版本上。
2. **离线确定性**：评分引擎为纯函数，同输入必得同输出。切片乱序、重复回放所得
   风险时间线完全一致；窗口由事件时间水位线定稿，定稿后不可重算。
3. **不补造数据**：传感器失联、时钟漂移、序列缺口、跨设备矛盾读数都只登记为
   质量事实并扣减置信度，系统从不插值、不挑选“看起来正常”的设备。置信度不足时
   高危判定只降不升，钳制到“现场复核”。
4. **建议可解释**：每个建议动作都快照规则号、触发阈值、实测值、校准编号、输入
   窗口、模型与协议版本，可随时回答“为什么要求撤离/转运”。
5. **处置留痕**：高危信号依次触发 现场复核 → 降温补水 → 转运；转运须值班军医
   下令；军医可覆盖系统建议但**理由必填**。所有记录写入哈希链日志，篡改可检出。
6. **最小知情**：指挥人员只看编组状态与待执行处置，看不到生理数值与完整档案；
   军医视图才包含规则阈值、校准与评估细节。

## 模块

| 文件 | 职责 |
| --- | --- |
| `protocol.py` | 冻结协议：版本/哈希、阈值档位、设备校准、风险方案、任务剖面 |
| `timeutil.py` | UTC 时间解析与固定窗口归并 |
| `engine.py` | 纯函数规则评分、置信度扣减与等级钳制 |
| `timeline.py` | 乱序/重复/冲突/迟到切片处理、水位线定稿、缺口与漂移判定 |
| `journal.py` | 追加式哈希链日志（只追加，可校验篡改） |
| `mission.py` | 任务冻结、状态机、动作处置、军医覆盖与解除 |
| `views.py` | 指挥人员/军医/卫生员/任务人员四种履职视图 |
| `sync.py` | 断网回连后按设备序列定序、幂等、按协议哈希守门的安全合并（含冲突登记回放） |
| `service.py` | HTTP 入口，可完全离线运行 |

状态机：`监测中 → 需复核 → 已预警 → 干预中 → 已解除`。

## 运行与测试

```bash
python3 service.py --check        # 校验冻结协议并打印版本哈希
python3 service.py --port 8000    # 启动离线边缘服务
npm test                          # 50 项测试：引擎/时间线/任务/合并/HTTP 契约
python3 -m compileall -q .        # 编译检查全部 Python 模块
```

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/missions` | 任务开始：冻结协议、编组与剖面，返回协议哈希 |
| POST | `/missions/{id}/ingest` | 离线接收一个生命体征切片（含设备 seq/时钟） |
| POST | `/missions/{id}/heartbeat` | 处理时间心跳，推动水位线定稿 |
| GET  | `/missions/{id}/status?subject_id=` | 单人状态、动作及依据 |
| GET  | `/missions/{id}/view?role=&subject_id=` | 按角色裁剪的履职视图 |
| POST | `/missions/{id}/actions` | 登记现场复核/降温补水/转运（含角色校验） |
| POST | `/missions/{id}/override` | 值班军医覆盖，`reason` 必填 |
| POST | `/missions/{id}/resolve` | 军医解除 |
| POST | `/missions/{id}/close` | 关闭任务，拒绝再写入 |
| GET  | `/missions/{id}/journal` | 导出日志并校验哈希链完整性 |
| POST | `/missions/{id}/sync/export` · `/sync/merge` | 边缘导出 / 回连安全汇入 |

## 确定性与延迟

- 窗口长 60 s、发射周期 30 s、允许迟到 120 s（均在冻结协议中）。
- 定稿延迟上界 = 允许迟到 + 一个发射周期（水位线只在收包或心跳时推进）。
- 同 `slice_id` 且设备、序号、采样时间与全部校准前读数逐字节语义一致的
  重复投递幂等；同 `slice_id` 但上述任一内容变化的投递（疑似固件回滚或
  缓存损坏）按 `SLICE_CONFLICT` 拒绝：不进入窗口、不推进风险等级，冲突
  本身写入哈希链日志并按角色进入视图（军医见双向内容哈希与差异字段，
  卫生员见设备与差异字段，指挥只见计数）；同设备同序号换切片按
  `SEQ_CONFLICT` 拒绝；定稿窗口后的迟到切片登记 `LATE_AFTER_FINALIZED`，
  不参与重算。
- 冲突登记随合并包回放：离线汇入或任务重建后，任一节点对同一编号切片的
  重复/冲突判断与首次接收节点一致。
- 缺口在窗口定稿时按全局已收序号判定，离线缓存造成的乱序不会被误判成丢片。

`fixtures/incidents.json` 内置高温与高原两段事件切片，测试以随机乱序 + 全量重复
方式回放，校验两种场景下风险时间线均为 `normal → review → alert → intervene`，
且不同随机种子结果逐字节一致。
